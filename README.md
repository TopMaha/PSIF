## ทำให้เป็นฐานข้อมูลออนไลน์ (ทุกคนเห็นข้อมูลเดียวกัน)

> เครื่องนี้ deploy Worker ไม่ได้ (Node เก่า/ไม่มี wrangler) — ทำตามขั้นตอนด้านล่างบนเครื่องที่มี
> Node 18+ หรือทำผ่านหน้าเว็บ Cloudflare Dashboard

### A. ติดตั้ง wrangler (เครื่องที่ deploy)
```bash
npm install -g wrangler
wrangler login
```

### B. สร้าง D1 + R2
```bash
wrangler d1 create psif-db
wrangler r2 bucket create psif-photos
wrangler d1 execute psif-db --remote --file=./schema.sql
```
คัดลอก `database_id` ที่ได้จากคำสั่งแรกไปใส่ `wrangler.toml`

### C. สร้าง `wrangler.toml` (วางไว้โฟลเดอร์เดียวกับ `worker.js`)
```toml
name = "psif-api"
main = "worker.js"
compatibility_date = "2024-09-01"

[[d1_databases]]
binding = "DB"
database_name = "psif-db"
database_id = "<<วาง database_id ที่ได้จากขั้น B>>"

[[r2_buckets]]
binding = "BUCKET"
bucket_name = "psif-photos"

# (ไม่บังคับ) ถ้าเปิด Public access / Custom domain ให้ R2 แล้ว
# ใส่ URL ฐานไว้ตรงนี้ เพื่อให้รูปโหลดตรงจาก R2 (ลดภาระ Worker)
# [vars]
# R2_PUBLIC_BASE = "https://pub-xxxxxxxx.r2.dev"
```

### D. Deploy
```bash
wrangler deploy
```
จะได้ URL เช่น `https://psif-api.<ชื่อบัญชี>.workers.dev`

### E. เชื่อมแอปกับ API
เปิดแอป → เมนู **⚙️ ตั้งค่า → ฐานข้อมูลออนไลน์ (API)** → วาง URL → **บันทึก & เชื่อมต่อ**
ทุกคนที่ใส่ URL เดียวกันจะเห็น/แก้ไขข้อมูลร่วมกัน

> **ทางเลือกผ่าน Dashboard (ไม่ใช้ command line):** Cloudflare → Workers & Pages → Create Worker →
> วางโค้ด `worker.js` → ในแท็บ Settings ผูก Binding ชื่อ `DB` (D1) และ `BUCKET` (R2) →
> รัน `schema.sql` ในหน้า D1 Console → Deploy

## 📷 การเก็บรูปภาพ (ประหยัดพื้นที่)
- **ไฟล์รูปจริงเก็บบน Cloudflare R2** — ฐานข้อมูล D1 เก็บแค่ "คีย์" (ข้อความสั้น เช่น
  `psif/12/after-….jpg`) ไม่ได้เก็บไฟล์รูป → D1 เล็กมาก ไม่บวม
- **ย่อรูปอัตโนมัติฝั่งผู้ใช้** ก่อนอัปโหลด (ด้านยาว ≤ 1600px, JPEG q0.82 ≈ 250–420 KB/รูป)
  ปรับความชัด/ขนาดได้ที่ตัวแปร `PHOTO_MAX` และ `PHOTO_QUALITY` ใน `index.html`
  - R2 ฟรี 10 GB ≈ ~12,000 งาน (งานละ 2 รูป) — อยากชัดขึ้นเพิ่มเป็น 1920px ได้ (ไฟล์โตขึ้นเล็กน้อย)
  - D1 เก็บแค่คีย์รูป จึงไม่มีทางทำให้ฐานข้อมูลเต็ม
- **ลบรูปออกจาก R2 อัตโนมัติ** เมื่อ Admin ลบรายการ (`DELETE /psif`)
- เสิร์ฟรูป 2 แบบ:
  1. ผ่าน Worker `GET /photo/:key` (ค่าเริ่มต้น — ใช้ได้เลย, รูปเป็นส่วนตัว)
  2. ตรงจาก R2 public/custom domain — ตั้ง `R2_PUBLIC_BASE` (ดูขั้น C) เพื่อลดภาระ/ค่า request ของ Worker
- โหมดทดลอง (ยังไม่ตั้งค่า API): รูปเก็บแบบ base64 ในเครื่อง (localStorage) ชั่วคราวเท่านั้น —
  พอเชื่อม API/deploy Worker แล้ว รูปจะไปอยู่บน R2 ทันที

## การทำงานของ 4 ขั้นตอน (ข้อ 1)
1. **บันทึกเข้าระบบ** — พนักงานกรอกฟอร์ม · แนบรูป "ก่อนแก้ไข" **บังคับเฉพาะประเภท PSIF (Con)**
   (ประเภทอื่นซ่อนช่องรูป ไม่ต้องแนบ — ตรวจซ้ำทั้ง frontend และ backend)
2. **Safety อนุมัติ/ไม่อนุมัติ** — เจ้าหน้าที่ Safety/Admin ตรวจเนื้อหา + ดูเรื่องซ้ำ
3. **กำลังดำเนินการ** — เริ่มได้เมื่อ **Admin "เปิดดำเนินการ"** ของหน่วยงานนั้น (ข้อ 6) แล้วใส่เลข No.PSIF
4. **เสร็จ** — ปิดงาน · แนบรูป "หลังแก้ไข" บังคับเฉพาะ PSIF (Con)

ระบบกัน **บันทึกซ้ำ** อัตโนมัติ: ปุ่มบันทึกล็อกทันทีที่กด + ทุกการบันทึกส่ง `requestId` (UUID)
ให้ Worker ตรวจซ้ำ (idempotency) และมี unique index ที่ D1 เป็นชั้นสุดท้าย
(DB ที่มีอยู่แล้วต้องรัน `migrate-2026-07-15-idempotency.sql` หนึ่งครั้ง)

## สิทธิ์ผู้ใช้ (เช็คจริงที่ Backend — role อ่านจากตาราง employees ผ่าน header `X-Emp-Id`)
- `user` — บันทึก/ปิดงานของตัวเอง (หน่วยงานระบุอัตโนมัติจากทะเบียนพนักงาน)
- `teamleader` / `manager` — เท่า user + ดูรายคนของกลุ่มตัวเองบนแดชบอร์ด
- `dept_admin` — **Admin แผนก**: เห็น/ติดตาม/ดำเนินการ (ออกเลข No., ปิดงาน, แก้เนื้อหา)
  เฉพาะแผนกตัวเอง (ช่องหน่วยงาน/VSM = แผนก, กรองที่ query ฝั่ง Worker) · Export Report ได้ ·
  **เข้าหน้าตั้งค่าไม่ได้**
- `safety` — อนุมัติ Safety + แก้ไขเนื้อหา + Export Report · **เข้าหน้าตั้งค่าไม่ได้**
- `admin` — **Super Admin**: ทุกแผนก + หน้าตั้งค่าทั้งหมด (ข้อมูลหลัก, เปิดดำเนินการ,
  เป้าหมาย, นำเข้า Excel, ลบรายการ)

ปุ่ม **Report** ส่งออกไฟล์ **Excel (.xlsx)** รายละเอียดครบทุกฟิลด์ ตาม filter ที่เลือกอยู่บนหน้าจอ

## 📊 Export Excel — รายงานรายคน สำหรับหัวหน้า (v1.7)
ตอบคำถาม “ใครเหลือกี่เรื่อง ประเภทอะไรบ้าง” — ไฟล์ .xlsx จัดรูปแบบพร้อมส่งหัวหน้า
(ตรึงหัวตาราง · ตัวกรอง · แถบสลับสี · เขียว = ครบเป้า / แดง = ยังขาด)

**เปิดใช้ได้ 2 ทาง**
- แดชบอร์ด → แตะกลุ่ม VSM/หน่วยงาน (หรือชิป **👥 ทีมของฉัน**) → ในป๊อปอัพรายคน กดปุ่ม **📊 Export Excel — รายงานรายคน**
  → ได้เฉพาะกลุ่มนั้น · สิทธิ์: Team Leader/Manager ของกลุ่มนั้น, Admin แผนก, Safety, Super Admin
- แดชบอร์ด → ชิป **📊 Excel รายคน (ทุกกลุ่ม)** → ได้ทุกกลุ่มในไฟล์เดียว
  · สิทธิ์: Admin แผนก (เห็นเฉพาะแผนกตัวเอง) / Safety / Super Admin

**3 ชีตในไฟล์เดียว**
1. **รายคน** — การ์ดสรุปด้านบน (ทั้งหมด/ครบเป้า/ยังไม่ครบ/ต้องส่งเพิ่มอีกกี่เรื่อง) + ตารางรายคน:
   ทำได้–ขาด แยก 3 ประเภท, เหลือรวม, ประเภทที่ยังขาด, ส่งทั้งหมด, ผ่านเกณฑ์, ความคืบหน้า %, สถานะ, โบนัสส่วน PSIF + แถวรวม
2. **สรุปตามประเภท** — ภาพรวมต่อประเภท (เป้ารวม/ทำได้/ขาดรวม/คนที่ครบ) และแยกตามหน่วยงาน/VSM ว่ากลุ่มไหนต้องเร่ง
3. **ต้องตามงาน** — เฉพาะคนที่ยังไม่ครบ เรียงขาดมาก → น้อย สำหรับหัวหน้าใช้ตามงาน

ตัวเลขทั้งหมดใช้เกณฑ์เดียวกับแดชบอร์ด (นับเฉพาะ Safety **อนุมัติ** + **จบงาน**) และไม่ขึ้นกับคำค้น/หน้าที่เปิดอยู่บนจอ
ไฟล์สร้างด้วย JS ล้วนในเครื่อง (ไม่พึ่ง CDN/ไลบรารีภายนอก) จึงใช้งานออฟไลน์ได้

## 👥 พนักงานลาออก / เปลี่ยนรหัสพนักงาน (v1.8)

- กด **🚪 พนักงานลาออก** → ข้อมูล PSIF ทั้งหมดของคนนั้นย้ายไปรวมที่ช่องว่างของแผนก
  แล้วรหัสเดิมถูก **ปิดใช้งาน** (เข้าระบบไม่ได้ · ไม่ถูกนับเป็นหัวคน) — ข้อมูลเดิมยังอยู่ครบในระบบ
- ช่องว่าง **ไม่ถูกนับเป็นหัวคน** ในเป้าหมาย/โบนัส/รายงานรายคน (แต่เรื่องของช่องว่างยังนับรวมในภาพรวมแผนก)
  จึงล็อกอินด้วยรหัสช่องว่างไม่ได้

**2) เปลี่ยนรหัสพนักงาน (คนเดิม รหัสใหม่)**
- กด **🔁 เปลี่ยนรหัสพนักงาน** → ใส่รหัสใหม่ (เช่น `S-057` → `T-815`)
- ข้อมูล PSIF เดิมทั้งหมด + ประวัติผู้ปิดงาน/ผู้ตรวจ + การแจ้งเตือน ย้ายไปรหัสใหม่ และ **รหัสเก่าถูกลบออก**
  ข้อมูลใหม่หลังจากนี้อยู่ที่รหัสใหม่ทั้งหมด (ถ้ารหัสใหม่มีอยู่แล้ว ระบบจะรวมข้อมูลเข้าด้วยกัน)
- ถ้าเปลี่ยนรหัสของบัญชีที่กำลังใช้งานอยู่ แอปจะอัปเดตตัวตนให้ทันที ไม่ต้องล็อกอินใหม่

ทั้งสองอย่างทำงานผ่าน `POST /employees/transfer` `{from,to,mode:'rename'|'resign'}` — Worker ตรวจสิทธิ์ Super Admin เอง
(ต้อง `wrangler deploy` ก่อนใช้งานจริง)

## 📥 วางรายชื่อพนักงานจาก Excel — ทีเดียวหลายคน (v2.2)
เดิมเพิ่ม/แก้พนักงานได้ทีละคนเท่านั้น v2.2 เพิ่มการ์ด **📥 วางรายชื่อพนักงานจาก Excel** ไว้ใต้ตาราง 👥 พนักงาน
ในหน้าตั้งค่า (เฉพาะ **Super Admin**) — คัดลอกจาก Excel มาวางได้เลย **การ์ดเดียวทำได้ 3 งาน** เลือกโหมดด้านบน

| โหมด | คอลัมน์ที่วาง (คั่นด้วย Tab) | ผลที่เกิด |
|---|---|---|
| ➕ **เพิ่ม/แก้ไขรายชื่อ** | รหัสพนักงาน · ชื่อ-สกุล · หน่วยงาน/VSM · สิทธิ์ | รหัสใหม่ = เพิ่ม · รหัสที่มีอยู่ = แก้ไขข้อมูลเดิม (ไม่สร้างซ้ำ) |
| 🚪 **พนักงานลาออก** | รหัสพนักงาน (คอลัมน์ 2 ใส่ชื่อไว้ตรวจทานได้) | ย้ายข้อมูล PSIF ไป "ช่องว่าง" ของแผนก แล้วปิดรหัสเดิม |
| 🔁 **เปลี่ยนรหัสพนักงาน** | รหัสเดิม · รหัสใหม่ · ชื่อ-สกุล · หน่วยงาน/VSM | ย้ายข้อมูลเดิมไปรหัสใหม่ แล้วลบรหัสเก่าออก |

**ต้องกด 🔎 ตรวจสอบ/พรีวิว ก่อนเสมอ** ปุ่มยืนยันจะเปิดก็ต่อเมื่อพรีวิวแล้ว — พรีวิวบอกครบว่า

- **กี่คน** แยกเป็น เพิ่มใหม่ / อัปเดตของเดิม / ซ้ำ-เหมือนเดิม / ซ้ำในรายการที่วาง / ข้าม
- **ซ้ำกันหรือไม่** — ซ้ำกับรหัสที่มีในระบบ (บอกด้วยว่าจะเปลี่ยนอะไรบ้าง เช่น `หน่วยงาน VSM4 → VSM7`) และซ้ำกันเองในรายการที่วาง (ใช้แถวแรก)
- **หรือเป็นคนเดิมที่เปลี่ยนรหัส** — ถ้าชื่อซ้ำกับพนักงานที่มีอยู่แล้วแต่คนละรหัส จะเตือนว่าเพิ่มแบบนี้จะกลายเป็น 2 คน
  พร้อมปุ่ม **🔁 ย้ายคนเหล่านี้ไปโหมดเปลี่ยนรหัสพนักงาน** (เตรียมรหัสเดิม → รหัสใหม่ให้เสร็จ กดพรีวิวต่อได้เลย)
- **จะย้ายข้อมูลกี่เรื่อง** (โหมดลาออก/เปลี่ยนรหัส) และจะสร้าง "ช่องว่าง" ให้แผนกไหนบ้าง
- ตารางรายแถวทุกแถว (แสดงสูงสุด 200 แถว) พร้อมเหตุผลของแถวที่ถูกข้าม

กันพลาดไว้ให้แล้ว: เว้นคอลัมน์หน่วยงาน/สิทธิ์ของคนที่มีอยู่แล้ว = **ใช้ค่าเดิม ไม่ล้างทิ้ง** · วางสลับ "ชื่อ | รหัส"
ระบบสลับให้เองแล้วบอกไว้ในพรีวิว · ห้ามใช้รหัส `RESIGNED-*` · ลาออก/เปลี่ยนรหัสของบัญชีที่กำลังใช้งานอยู่ถูกกันไว้
(เปลี่ยนรหัสตัวเองผ่านโหมดนี้ได้ แอปสลับตัวตนให้ทันที) · การไล่รหัสไขว้กันเอง (A→B, B→C) ถูกกันไว้ ให้ทำทีละคนแทน

ทำงานผ่าน `POST /employees/bulk` `{mode:'upsert'|'resign'|'rename', rows:[...]}` — Worker ทำทีละแถว
แถวที่พังไม่ทำให้ทั้งชุดล้ม แล้วคืนผลรายแถวมาบอกว่าแถวไหนไม่สำเร็จเพราะอะไร (Super Admin เท่านั้น · ต้อง `wrangler deploy` ก่อนใช้)

## ⏳ เรื่องที่ส่งแล้วแต่ยังไม่นับ — หน้า "ของฉัน" (v1.9)
แก้ปัญหาพนักงานสับสนว่า *"ลงเรื่องไปแล้ว ทำไมตัวเลขไม่ขึ้น"* เพราะระบบนับเฉพาะเรื่องที่ **อนุมัติ + จบงาน**
หน้าแดชบอร์ด → 🙋 **ของฉัน** จึงแยกเรื่องที่ยังไม่นับออกเป็น **3 กลุ่ม** (ทุกเรื่องอยู่กลุ่มเดียวเท่านั้น)

| กลุ่ม | เงื่อนไข | นับผลงาน |
|---|---|---|
| ⏳ **Safety กำลังพิจารณา** | ส่งแล้ว Safety ยังไม่ตัดสิน | ยังไม่นับ |
| 🔧 **กำลังดำเนินการ** | Safety **อนุมัติแล้ว** แต่ยังไม่ปิดงาน | ยังไม่นับ (จะนับเมื่อปิดงาน) |
| ✖️ **ไม่ผ่านการพิจารณา** | ซ้ำ / ไม่เข้าข่าย Cardinal rules / ไม่อนุมัติ | ไม่นับ |

สิ่งที่แสดงเพิ่ม
- **ชิปสรุป 3 กลุ่ม** ใต้กล่องสถิติ — แตะเพื่อดูรายการในกลุ่มนั้น (แตะรายการต่อเพื่อเปิดรายละเอียด)
- **แถบรายประเภท** เพิ่มส่วนแถบลาย: 🟪 กำลังดำเนินการ · 🟧 รอ Safety ต่อจากแถบทึบ (ที่นับแล้ว)
  พร้อมป้าย `🎯 ถ้าผ่านครบ → n/2` บอกว่าถ้าอนุมัติหมดจะได้กี่เรื่องต่อประเภท
- **ถ้าเรื่องที่ค้างผ่านครบ → ...** ใต้กล่อง "นับผลงาน" (กี่เรื่อง) และกล่อง "โบนัสส่วน PSIF" (กี่ %)
- ป๊อปอัพคำอธิบายโบนัสมีกล่อง ⏳ สรุปเรื่องค้าง + ส่วน PSIF จะขยับจากกี่ % เป็นกี่ %

ตัวเลข **นับผลงาน / โบนัส / เป้าหมาย ยังใช้เกณฑ์เดิมทุกอย่าง** — ส่วนนี้เป็นการแสดงผลเพื่อความเข้าใจเท่านั้น

## 📥 ยอด "ส่งแล้ว" แยกตัวหลัก/ตัวรอง — แดชบอร์ดทั้งโรงงาน (v2.0)
เดิมไทล์ "ส่งแล้ว" แสดงจำนวนเรื่องที่เข้ามา**ทั้งหมด** ทำให้ยอดถูกดันด้วยเรื่องที่ยังไม่ผ่านเกณฑ์
v2.0 แยกเป็น 2 ชั้นในไทล์เดียว

| ชั้น | ประกอบด้วย | แสดงผล | นับเข้า % ของเป้าหมาย |
|---|---|---|---|
| **ตัวหลัก** | Safety อนุมัติแล้ว → 🔧 กำลังดำเนินการ + 🏁 จบงาน | ตัวเลขใหญ่ | ✅ นับ |
| **ตัวรอง** | ⏳ รอ Safety + ✖️ ไม่ผ่าน (ซ้ำ/ไม่เข้าข่าย/ไม่อนุมัติ) | ตัวเล็กจางๆ `+n` และบรรทัดย่อย | ❌ ไม่นับ |

- `% ของเป้าหมาย` ในไทล์คิดจาก **ตัวหลัก ÷ Target** (เดิมคิดจากยอดรวมทั้งหมด)
- ไทล์ "นับผลงาน" เปลี่ยนตัวหารเป็น `% ของที่ผ่าน Safety` (เดิมเทียบกับยอดส่งทั้งหมด)
- **แตะที่ไทล์** เพื่อเปิดคำอธิบายแยกรายกลุ่ม + "ถ้า Safety อนุมัติเรื่องที่รออยู่ทั้งหมด ตัวหลักจะเป็นเท่าไร"
- แถบความคืบหน้า · กราฟรายประเภท · VSM/หน่วยงาน · โบนัส **ใช้เกณฑ์เดิม (อนุมัติ+จบงาน)** ไม่เปลี่ยน
- การ์ด "📊 สถานะงาน" (โดนัท) และกราฟส่งรายเดือน ยังนับ**ทุกเรื่องที่ส่งเข้ามา** ตามเดิม

## 📷 รูป "ก่อน / หลังแก้ไข" ของ PSIF (Con) ต้องครบ + ⚠️ ชิปตามเก็บรูป (v2.1)
กฎเดิม: PSIF (Con) ต้องแนบ**รูปก่อนแก้ไข**ตอนบันทึก และ**รูปหลังแก้ไข**ตอนปิดงาน (ประเภทอื่นไม่บังคับ)
แต่พบว่ามีบางรายการหลุดเข้าระบบมาโดยไม่มีรูป v2.1 จึงทั้ง **อุดช่องโหว่** และ **ตามเก็บย้อนหลัง**

**เห็นได้ทันทีว่ารายการไหนรูปขาด**
- การ์ดในหน้าติดตาม/Safety ขึ้นป้ายแดง `📷 ขาดรูปก่อนแก้ไข` / `ขาดรูปหลังแก้ไข` + โชว์กรอบรูปว่างไว้เสมอ
- ชิป `⚠️ ขาดรูป (n)` ท้ายแถวสถานะหน้าติดตาม — กรองเฉพาะรายการที่ต้องตามเก็บ (**ไม่มีของค้าง = ชิปหายไปเอง**)
- ในรายละเอียดมีกล่องเตือน + ปุ่ม **“📷 แนบรูป…ย้อนหลัง”** ใต้ช่องที่ขาด
  (สิทธิ์: เจ้าของเรื่อง · Admin แผนกนั้น · Safety · Super Admin — เช็คซ้ำที่ backend)
- Report `.xlsx` เพิ่มคอลัมน์ **ขาดรูป (ต้องแนบย้อนหลัง)** เอาไปไล่ตามเก็บได้

**ไม่นับข้อมูลที่ย้ายมาจากระบบเดิม** (ตามคำขอ) — ถือเป็น "ข้อมูลเก่า" เมื่อเข้าข้อใดข้อหนึ่ง
| เกณฑ์ | ค่า | ตัวแปรใน `index.html` |
|---|---|---|
| อยู่ในชุดนำเข้าเดิม (123456.xlsx) | `id` ≤ 1702 | `LEGACY_MAX_ID` |
| บันทึกก่อนวันที่แอปเริ่มบังคับแนบรูป (v1.0) | ก่อน 2026-07-16 | `PHOTO_RULE_SINCE` |
| นำเข้าผ่านเมนู "นำเข้าจาก Excel" | `request_id` ขึ้นต้น `import-` | (worker ติดป้ายให้อัตโนมัติ) |

เรื่องที่ Safety ตีตกแล้ว (ซ้ำ / ไม่เข้าข่าย) ก็ไม่ต้องตามเก็บรูปเช่นกัน
**ปิดงานไม่ถูกบล็อก** ถ้ารูปก่อนแก้ไขหาย — ย้อนไปถ่ายใหม่ไม่ได้แล้ว ระบบแค่เตือนจนกว่าจะแนบครบ
(เลื่อนเส้นแบ่ง "ข้อมูลเก่า" ได้โดยแก้ 2 ค่าบนสุดของบล็อก `รูป "ก่อน / หลังแก้ไข"` ใน `index.html`)

**อุดช่องโหว่ฝั่ง API (`worker.js`)**
- `POST /psif` ที่ `request_id` ซ้ำ (กดบันทึกซ้ำ/ลองใหม่หลังพลาด) เดิมคืนแถวเดิมเฉย ๆ —
  ถ้ารอบก่อนบันทึกแถวสำเร็จแต่ผูกรูปไม่สำเร็จ แถวนั้นจะไม่มีรูปตลอดไป → ตอนนี้เติมรูปที่ยังขาดให้ก่อนคืน
- `PATCH /psif/:id` การแนบรูปเดิม**ไม่เช็คสิทธิ์เลย** → จำกัดเป็น เจ้าของเรื่อง/Admin แผนกนั้น/Safety/Super Admin
  และแนบรูปอย่างเดียวก็ขยับ `updated_at` ให้
- แก้ประเภทเป็น PSIF (Con) ทีหลังแล้วรูปไม่ครบ → เด้งข้อความเตือนทันทีหลังบันทึก
